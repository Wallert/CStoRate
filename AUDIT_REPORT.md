# Аудит і виправлення CStoRate

Дата: 3 жовтня 2026 року. Перевірено розархівовану версію 1.0.2; результат виправлень — версія 1.0.3. Цей звіт фіксує перевірки перед публікацією. Стан розгортання доступний у GitHub Actions, а версія опублікованого сайту — у його footer.

Перевірено всі 24 власні файли початкового проєкту: застосунок, HTML, CSS, документацію, конфігурацію, залежності й тести. Код сторонніх пакетів у `node_modules`, Git internals і дубль джерел у `CStoRate.rar` не входили до огляду коду. Базу відомих вразливостей npm перевірено окремо після завершення огляду джерел.

Найсуттєвіші проблеми стосувалися втрати чернеток і недостовірного статусу збереження. Вони виправлені разом із помилками ідентифікаторів, переміщення карток, асинхронних запитів та тестового середовища. Підтверджених критичних вразливостей власного коду не виявлено в перевіреному обсязі; це не гарантія відсутності інших проблем.

Текст з імпорту, посилань і Steam залишається текстом через DOM `textContent`/`value`; кольори, ідентифікатори й протоколи зображень обмежуються валідатором. Підтверджених шляхів DOM XSS або prototype pollution не знайдено. Додано тест буквальних JSON-ключів `__proto__` і `constructor` у realm застосунку. Поточні CSP і SRI збережені.

## Збереження і відновлення

- `saveAutoSave` повертає результат запису. Помилка залишає стан dirty, показує видимий статус і одноразове повідомлення з пропозицією Save JSON; наступні спроби можуть зберегти дані. Зміни також записуються при `pagehide` і приховуванні вкладки.
- Створення, оновлення, клонування і видалення записів бібліотеки застосовуються до пам'яті після успішного запису localStorage. При відмові немає «збережених» записів, яких насправді немає у сховищі.
- Ідентифікатор активного запису зберігається одразу після Save List, тому перезавантаження не створює зайву копію при наступному збереженні.
- Перед JSON-імпортом, завантаженням посилання/бібліотеки та Reset All зберігається одна попередня дошка. Кнопка Restore previous board працює після перезавантаження і дозволяє перемикатися між двома станами. Якщо резервний запис не вдається, заміна не відбувається; користувач отримує пропозицію завантажити JSON.
- Тимчасово порожня назва під час редагування більше не робить чернетку невалідною після перезавантаження. Для запису чернетки/експорту використовується стандартна назва; Save List просить ввести назву.
- Обмеження 50 tier rows і 1000 games діють також при ручному додаванні. Не можна створити дошку, яку той самий застосунок потім відкине через кількість елементів.

Відновлення — один попередній стан, а не повна історія Undo. Бібліотека і чернетки прив'язані до browser origin та профілю: localhost і GitHub Pages мають різні сховища. Save JSON залишається переносною резервною копією.

## Взаємодія і запити

- Переміщення перевіряє джерело, призначення і цільову картку до вилучення гри. Воно записується навіть при відсутньому старому DOM-вузлі.
- Звичайний mouse click відкриває діалог переміщення; клавіатура після перенесення використовує актуальний рядок. Enter на вкладеному Steam link не відкриває другий діалог.
- Touch cancel, Escape і втрата фокусу прибирають drag mirror та блокування виділення без виконання drop. Відстежується палець, що почав жест; другий палець скасовує його.
- Вертикальні постери переставляються ліворуч/праворуч відповідно до розкладки рядка.
- Запити Steam та FileReader більше не можуть застосувати застарілий результат після іншого імпорту або Reset All. Завершення старого запиту не розблоковує контролі нового.
- Відповідь провайдера з невалідною структурою запускає наступний fallback. Кеші обмежені 100 записами кожен. Часові обмеження та явні помилки збережені.
- Autocomplete підтримує Arrow Up/Down, Home/End, Enter, Escape і Tab з combobox/option ARIA. Escape та клік поза пошуком скасовують очікування.
- Генератор share link використовує той самий ліміт 500000 символів, що й читач. Для надто великої дошки пропонується Save JSON. Clipboard fallback прибирає тимчасове поле навіть при помилці й повертає фокус.

## Експорт і інтерфейс

PNG export захищений від паралельних запусків, повертає початкові стилі контролів після помилки, використовує Blob у браузерах із відповідною підтримкою та обмежує розміри canvas: до 16000 px на сторону і 32 млн пікселів. Для надто великої дошки є явна помилка. Імена файлів очищаються від символів, заборонених у Windows.

Збережено темну неонову візуальну мову. Покращено читабельність приглушеного тексту, колір тексту на власних tier colors, видимість keyboard focus, skip link, прокрутку довгих модальних вікон і reduced-motion/forced-colors стани. На вузьких екранах row action controls перенесено в окрему смугу з цілями 44×44 px; порожні мітки рядків мають мінімальну висоту 48 px.

## Локальний запуск і архітектура

`scripts/dev-server.js` замінює неприкріплений `npx http-server`. Він використовує стандартні модулі Node.js, слухає тільки `127.0.0.1`, віддає лише три файли сайту та два дозволені Steam API endpoints. Немає directory listing або доступу до `.git`, архіву чи `node_modules`. Proxy не приймає довільний URL, не пересилає браузерні cookies/headers, забороняє redirects, має timeout 6.5 s і бюджет відповіді 5 MiB. Ізольовані HTTP-тести перевіряють ці контракти без реального Steam.

`applyBoard`, `boardSnapshot`, спільні ліміти та allocator ідентифікаторів зменшують розбіжності між імпортом, бібліотекою, чернетками й share workflow. Основний контролер залишається vanilla JS без нової framework-залежності. `start.bat` спочатку переходить у власну папку, тому працює незалежно від поточного каталогу запуску.

## Що залишається залежним від середовища

1. **Публічний Steam proxy.** GitHub Pages не має backend. Jina/AllOrigins можуть бути недоступні або обмежувати запити. Для власного same-origin proxy додано opt-in конфігурацію, описану в DEPLOYMENT.md; її продакшн-розгортання тут не виконувалося.
2. **Експорт зображень.** CORS сторонніх image hosts, мережа, підтримка CSS бібліотекою html2canvas і canvas limits браузера можуть вплинути на PNG. Зробити ручний pixel check перед публікацією.
3. **Платформи.** Реальний iPhone/Safari, multi-touch на фізичному пристрої, screen reader та повний WCAG audit не виконувалися. Touch і cancellation контракти перевірено у DOM-тестах; вузький viewport — у браузері.
4. **Публікація.** CI workflow містить автоматичні перевірки. На момент завершення цього аудиту віддалений запуск і GitHub Pages deployment ще не перевірялися; їх потрібно підтверджувати за результатами GitHub Actions та версією live-сайту після push/deploy.

## Подальша підтримка

Виправлення безпеки, збереження й переміщення завершені та покриті регресіями. Наступний корисний крок для розгортання — стабільний власний Steam proxy і браузерні end-to-end тести з перевіркою завантажених PNG/JSON. За подальшого росту функцій варто розділити контролер на модулі storage, Steam, interaction і rendering; критерій приймання — незмінний формат збережених даних та проходження поточного набору тестів. Ці майбутні можливості не позначено як уже реалізовані.
